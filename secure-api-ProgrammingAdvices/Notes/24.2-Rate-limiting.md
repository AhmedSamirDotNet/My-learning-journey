# 📖 Implement Rate Limiting in Student API
**(Fixed Window + Per IP + 429) — Practical Guide**

---

### 🗝️ Introduction
In this guide, we will implement a robust security layer to protect your API from brute-force attacks and resource exhaustion. We are adding **Rate Limiting** to the **Student API** using the built-in features of ASP.NET Core.

**Key Objectives:**
*   ✅ **Fixed Window**: A straightforward limiting strategy based on time slots.
*   ✅ **Per IP Strategy**: Identification and restriction based on the user's IP address.
*   ✅ **429 Too Many Requests**: Returning the standard HTTP status code for throttled requests.
*   ✅ **Targeted Protection**: Focused specifically on sensitive endpoints (Login & Refresh).

> 📌 **Note:** This implementation acts as a Middleware (a protective layer). It does not require any changes to your existing JWT or business logic inside your Controllers.

---

### 🔹 Step 1: Add Required `using` Statements
At the top of your `Program.cs` file, add the following namespaces to access the rate-limiting libraries:

using Microsoft.AspNetCore.RateLimiting;
using System.Threading.RateLimiting;

---

### 🔹 Step 2: Register Rate Limiting Service (DI)
You need to define the "Policy" that governs how the limiting works. Add this code in `Program.cs` before `builder.Services.AddControllers();`:

builder.Services.AddRateLimiter(options =>
{
    // Define the status code to return when a request is rejected
    options.RejectionStatusCode = StatusCodes.Status429TooManyRequests;

    // Create a policy named "AuthLimiter"
    options.AddPolicy("AuthLimiter", httpContext =>
    {
        // Identify the user by their remote IP address
        var ip = httpContext.Connection.RemoteIpAddress?.ToString() ?? "unknown";

        return RateLimitPartition.GetFixedWindowLimiter(
            partitionKey: ip,
            factory: _ => new FixedWindowRateLimiterOptions
            {
                PermitLimit = 5,              // Allow a maximum of 5 requests
                Window = TimeSpan.FromMinutes(1), // Within a 1-minute window
                QueueLimit = 0                // Reject immediately if limit is exceeded (no queuing)
            });
    });
});

---

### 🔹 Step 3: Add Rate Limiting Middleware
Now, tell the application pipeline to use this service. Add the following line in `Program.cs` **before** Authentication and Authorization:

app.UseHttpsRedirection();

app.UseRateLimiter();      // ✅ Crucial: Place before Auth to block abuse early

app.UseAuthentication();
app.UseAuthorization();

app.MapControllers();

---

### 🔹 Step 4: Prepare the AuthController
In your `AuthController.cs` file, add the rate-limiting namespace at the top:

using Microsoft.AspNetCore.RateLimiting;

---

### 🔹 Step 5 & 6: Apply the Policy to Endpoints
Apply the protection to specific actions using the `[EnableRateLimiting]` attribute. This ensures only these high-risk endpoints are throttled:

[HttpPost("login")]
[EnableRateLimiting("AuthLimiter")] // Activates the policy defined in Step 2
public IActionResult Login([FromBody] LoginRequest request)
{
    // Your existing login logic remains untouched
}

[HttpPost("refresh")]
[EnableRateLimiting("AuthLimiter")] // Protects the refresh token endpoint as well
public IActionResult Refresh([FromBody] RefreshRequest request)
{
    // Your existing refresh logic remains untouched
}

---

### 🔹 Step 7: What Happens When Limit Is Exceeded?
If a user attempts more than 5 requests within a single minute:
1. The request is intercepted and stopped at the Middleware layer.
2. The client receives an HTTP `429 Too Many Requests` response.
3. The Controller code is **never executed**, saving database connections and CPU cycles.

---

### 🔹 Step 8: Optional Custom Message (Recommended)
To provide a user-friendly message when a lockout occurs, add this logic in `Program.cs` immediately after `app.UseRateLimiter();`:

app.Use(async (context, next) =>
{
    await next();

    if (context.Response.StatusCode == StatusCodes.Status429TooManyRequests)
    {
        await context.Response.WriteAsync("Too many login attempts. Please try again later.");
    }
});

### 🧬 Characteristics & Benefits
*   **Targeted Protection**: Guards sensitive entry points without affecting public/low-risk data.
*   **Performance Efficient**: Blocks malicious traffic before it hits your heavy business logic.
*   **Standardized**: Uses the official HTTP 429 status, which modern browsers and clients understand.
*   **Clean Architecture**: Keeps security configuration in the pipeline rather than cluttering Controllers.

---

### 🔗 Interconnection Summary
*   **JWT**: Proves "Who" the user is.
*   **Rate Limiting**: Controls "How fast" a user can try to prove who they are.
*   **Resiliency**: By combining these, your API survives automated attacks and maintains stability for legitimate users.
