# 📖 Implementing Refresh Tokens
### Access Token + Refresh Token + Rotation + Logout (Student API, In-Memory)

---

## 🗝️ Introduction
Your current JWT login is correct, but it creates a real problem:
* **Access tokens expire** (good for security).
* **Users would need to re-login often** (bad for usability).

**Refresh tokens solve this by adding a renewal mechanism:**
* **Access Token:** short-lived, used to call Student endpoints.
* **Refresh Token:** long-lived, used only to get a new access token.

**In this lesson you will implement:**
1.  Login returns **AccessToken + RefreshToken**.
2.  Refresh endpoint issues a new **AccessToken** and **rotates RefreshToken**.
3.  Logout **revokes** refresh token (cuts the renewal path).

---

## 🎯 Outcome
By the end of this lesson, your API will support:
✅ **Short-lived access tokens** (safer)
✅ **Long sessions without re-login** (usable)
✅ **Refresh token rotation** (professional-grade)

## 🧱 Step 1 — Add Auth DTOs (Correct Placement)

**✅ Create folders**
Create this folder structure:
StudentApi
├─ DTOs
│  └─ Auth
│     ├─ TokenResponse.cs
│     ├─ RefreshRequest.cs
│     └─ LogoutRequest.cs

**✅ DTO: TokenResponse.cs**
namespace StudentApi.DTOs.Auth
{
    public class TokenResponse
    {
        public string AccessToken { get; set; }
        public string RefreshToken { get; set; }
    }
}

**✅ DTO: RefreshRequest.cs**
namespace StudentApi.DTOs.Auth
{
    public class RefreshRequest
    {
        public string RefreshToken { get; set; }
        public string Email { get; set; }
    }
}

**✅ DTO: LogoutRequest.cs**
namespace StudentApi.DTOs.Auth
{
    public class LogoutRequest
    {
        public string Email { get; set; }
        public string RefreshToken { get; set; }
    }
}

> 📌 **Note:** Your existing `LoginRequest` move it for consistency to `DTOs/Auth/LoginRequest.cs` as well.
